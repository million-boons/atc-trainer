1.1 Purpose

This SOP describes how to prepare, start, operate, test and shut down the offline voice ATC trainer, and how to record the results of a manual test on paper.

1.2 Scope

  • Operation by the instructor and the trainee on the training panel.
  • Manual acceptance tests of every screen that the build has: Dashboard, exercise, Exercise Planner, Phraseology Studio, Scenario Selection, Assessment, Settings.
  • Not in scope: installing or building the software, speech recognition accuracy testing, recording real voices.

1.3 Conventions

  • Bold words are words on the screen or buttons.
  • TO CONFIRM marks a point that is not proven by the documents or the code. Check it on the panel and correct this document.
  • A failed test line is a finding, not a stop, unless the line says so. Write the step number with every finding.
  • All exercise wording is PLACEHOLDER until the unit approves it. Practice only; Assessed is not available while a scenario's text is PLACEHOLDER.

2.3 H540 automatic gain control (AGC) off

The H540's AGC must be off and its capture level kept (D-37, D-51). On 2026-11-24 it read off with capture 70 %, but nothing on the panel enforced it then. The installer deploy/setup_panel.sh makes it persistent (AGC off, capture level kept at login and replug) and installs the pedal rule. The user ran it on the panel on 2026-11-27 (RESULT: PASS, D-339). Check at any time, without sudo: ./deploy/setup_panel.sh --verify (in .worktrees/runtime). If it fails, the user runs sudo ./deploy/setup_panel.sh again with the H540 and the pedal plugged in; report in ~/atc-setup-report.txt.

Manual check:

cat /proc/asound/cards                       # find the H540's card number N (a USB-Audio line)
amixer -c N controls | grep -i gain          # name of the AGC control
amixer -c N cget name='Auto Gain Control'    # must read "off"
amixer -c N cset name='Auto Gain Control' off   # only if it reads "on"

The control name "Auto Gain Control" is the one the installer's test uses; the real H540 name is TO CONFIRM (use the name the second command prints).

3. Start-up and shutdown

3.1 Start-up

  1. Complete the pre-checks of section 2.
  2. Open a terminal on the panel's own desktop (see 8.5 for SSH).
  3. Start the program, without --root (with it the voice bank of paths.conf is not read, D-308): 
    cd /home/user/projects/atc-trainer/.worktrees/runtime
./build/bin/atc_trainer --size 1280x800
    For the large layout: --size 1920x1080.
    Only if the pedal fails (fallback, D-338): add --ptt-device stand-in to use the right mouse button; PTT then shows STAND-IN. Run E5's setfacl line first.
  4. The Dashboard opens. Nobody is logged in. The status bar shows the chips Mic, Speaker, PTT, STT, VOICE BANK, the scenario, and the clock (UTC and local).
  5. Wait for VOICE BANK to go from CHECKING to COVERAGE OK by itself.
  6. Readiness (each tile states READY, WARNS or BLOCKS START):
    • Microphone: Test (5 s level). Speak normally; peaks around −12 dBFS, band −20 to −6 dBFS.
    • Speaker: Test tone, listen to the end, then I heard it. This is the only way to OK.
    • PTT: tile OK, "foot pedal (Preon)" (not STAND-IN). Test, hold the pedal 2 s: "Held 2.xx s: OK".
    • Speech model: Load exercise model (Whisper tiny + generated prompt). Wait for READY.
  7. START EXERCISE is enabled when no tile blocks. The footer names the tiles that block.

3.2 Shutdown

  1. End or stop any running exercise first (STOP asks for confirmation; an Assessed exercise needs the instructor PIN).
  2. Log out (Log out in the status bar).
  3. Close the program window. A dedicated Quit button: TO CONFIRM (none found in the screens).
  4. If the window is closed during an exercise, the exercise ends and its log says so ("program closed", D-333); see test T10.
  5. After a restart no plan is chosen (PB-5); saved plans, results and records stay.

4.1 Rules

  • After 5 wrong PIN entries the keypad says "Wait 60 s".
  • The instructor is logged out after 10 minutes without input (Settings > Instructor, 1 to 60 min), never during a transmission.
  • Logging in or out never stops a transmission and never blocks PTT; it is refused only while a transmission is open.
  • A trainee's plan on the Dashboard is put away when that trainee logs out, or when someone else logs in. A plan for Anyone stays.

4.2 Log out

Log out in the status bar. Always log out at the end of a session.

4.3 Set or change the instructor PIN

  • First time, in a terminal on the panel: cd /home/user/projects/atc-trainer/.worktrees/runtime && ./build/bin/set_instructor_pin
  • Later: Settings > Instructor > Change PIN... (old PIN, new PIN; 6 to 12 digits).
  • Never write the PIN in a file, a log or this document.

5. Instructor tasks

5.1 Trainee records

  • Settings > Trainee records: each trainee has an ID (e.g. S01) and a name, on this machine only. A physical keyboard is needed for IDs and names.

5.2 Consent

The consent texts are DRAFTS. Until the unit approves them (ST-5, D-134) nobody is asked for consent and NO REAL VOICE IS RECORDED. Recording tests use test tones and synthetic clips only.
  • Two separate answers per trainee: consent to be recorded, and pilot voice (the trainee's voice used as a pilot that others hear).
  • Without consent nothing of that trainee is stored. Exercise audio is never stored in this build (D-314).
  • When a consent text changes, the trainee is asked again at the next login; the answer is stored only after the instructor confirms with the PIN.
  • Withdrawn pilot-voice consent: the takes leave the voice bank at once; the Studio lists them as "Consent withdrawn".

5.3 Exercise plans (Training > Exercises)

  • New: name, scenario, trainee or Anyone, Practice or Assessed, Fixed or Random values, briefing (max 200 characters), difficulty preset, reply delays (0.3 to 5.0 s), radio effect. Then Save.
  • The card On the Dashboard shows the saved plan. While editing it says Unsaved changes; a plan never saved says Not saved yet. The checks read CHECKS OF THE EDIT while editing.
  • Assessed needs a trainee and a Validated scenario (not possible with PLACEHOLDER text).
  • Put on the Dashboard selects the plan. Presets... changes Easy, Normal, Hard; saved plans keep their values and offer "Use new preset values".

5.4 Phraseology Studio (Training > Phrases)

  • Choose a phrase; the strip under the text shows static parts ("S", solid) and slots ("D", dashed, mono) with a dot per clip: grey missing, amber recorded, green accepted.
  • A changed text becomes Draft. Save it first, then Validated (needs the SOP reference; refused while the file is PLACEHOLDER).
  • Listen: Raw, Trimmed, Radio, Sentence.
  • Test tones only until the consent texts are approved: no speech into RECORD.
  • "Save wording" writes the phraseology file in the data folder in use. For tests, use Undo.

5.5 Settings

  • Pages: General, Audio, PTT, Speech, Voice bank, Recordings, Trainee records, Instructor, About.
  • Theme, motion and clock apply now and may be changed by anyone. Everything else is instructor only and applies at the next start of the program.
  • Voice bank: choose the bank in use or a Studio bank (a Studio bank without accepted clips is off).
  • Device lists, pedal learning and the test sentence answer "not built" / "not available" in this build.
  • Restore starting values per page.

5.6 Deleting results

  • Only the instructor deletes; every deletion is logged first; nothing is deleted automatically.
  • Assessment > Delete result: one exercise log. Guest results: deleted together, as a count, from Settings (TO CONFIRM page).
  • Stored Lab recordings: Settings > Recordings, play or delete.

6. Trainee tasks

6.1 Choose the exercise

  • Log in with your ID (or practise as guest). On the Dashboard tap Choose plan: you see your plans and plans for Anyone. Or Choose scenario / nav rail Scenarios.
  • Read the scenario card: callsign, type, runway, taxiway, briefing.

6.2 Dashboard readiness

  • Start only when the footer does not say "Not ready to start". Microphone NOT TESTED and Speaker NOT CHECKED only warn; run their tests anyway.
  • START EXERCISE opens the Start dialog with the same values, the mode and the model ("locked at Start").

6.3 PTT technique

  • Press and hold PTT, then speak, release after the last word. PTT: the foot pedal; if it fails, Screen PTT or Space (and, if the program was started with the stand-in, the right mouse button).
  • TX (amber) = you transmit. RX (cyan) = the pilot speaks.
  • Lift your foot fully between transmissions. A press held more than 30 s is closed as STUCK ("Lift your foot to transmit again").
  • A short tap is not a transmission (Settings > PTT, "Short tap below", starting value 250 ms).
  • Pressing while the pilot speaks cuts the pilot off (PILOT CUT) in the departure scenario (rule "interrupt").
  • Do not release in the middle of a sentence ("Released early").

6.4 Speaking rules

  • Callsign first, then one instruction: "Eagle four two one, taxi via alpha three runway zero nine."
  • Digits one by one: "four two one", "zero nine", "two seven". "Niner" is accepted as nine, likewise "tree", "fife", "fower", "alfa".
  • Phonetic alphabet for letters: A3 = "alpha three", B2 = "bravo two".
  • Standard phraseology, even pace, normal loudness. Wait for the readback; correct it if wrong; repeat clearly after "say again".
  • No answer at all: check the callsign. The pilot answers only to their own callsign.

6.5 Practice and Assessed

  • Practice: the verdict of each instruction is shown at once.
  • Assessed: the verdict is hidden until the result. Not available while the text is PLACEHOLDER; a plan fixes the mode.

6.6 Reading the Result

  • Heading: COMPLETED, STOPPED BY INSTRUCTOR, TIME LIMIT, PROGRAM CLOSED or LOG INCOMPLETE.
  • Steps done, attempts, missed steps, response time (median), PTT notes (spoke before keying, released early, short taps, keyed over the pilot), fallback PTT used, speech model.
  • Suspected STT errors are listed apart and are never counted against the trainee. There is no pass mark.
  • Run again: same plan; random values are drawn and shown before the start.

9. Known limits (this build)

  • Placeholder wording. All scenario and phraseology text is PLACEHOLDER until validated against the approved SOP. Assessed mode is therefore not available; Practice only. There is no pass mark.
  • Pilot voice. The pilot clips are synthetic (Piper, voice en_US-norman-medium), made offline on the panel. The pilot says "niner". The user's listening check of the new clips (runway 09, hold short, spot check) is open (D-329).
  • One pedal. Only the Preon pedal (04d8:0055) is set up (D-338). Learning another pedal in Settings is not built yet; the mouse stand-in is a fallback only and needs setfacl after each replug.
  • Recognition speed and accuracy. Frequent "say again" is expected: the best measured result is 25 of 40 instructions fully correct, for one speaker. Release-to-text time on the panel is still to be measured (T2.11). This SOP's tests are not a speech accuracy test.
  • No exercise audio. Exercise audio is never stored (D-314); Assessment cannot play it.
  • No real voice recording until the unit approves the consent texts (ST-5).
  • Settings. Most changes apply at the next program start; device lists and the test sentence are not built.
  • Scenarios. The data has one scenario, Departure 01.
  • Not measured on the panel: frame time, memory, start-up time.
