## 3. TX states

Each state shows text, plus an icon for the fault states. Derived in `src/core/TxDisplay.h` (tested); the first matching row wins.

| State | Definition |
|---|---|
| TX | A transmission is open: the trainee is transmitting and the timer runs. |
| TAIL | PTT was released; the release tail (default 200 ms) is still being recorded. |
| STUCK | PTT is still held after the maximum duration (default 30 s) closed the transmission; it must be released before it can transmit again. |
| BLOCKED | Rule "block" only: PTT was pressed while the pilot was speaking, so the press is discarded; it stays until PTT is released, even if the pilot finishes. |
| WAIT (queued) | Rule "queue" only: PTT was pressed while the pilot was speaking and waits; sub-text "Queued – pilot speaking" in caution colour. If still held when the pilot finishes, TX opens then; if released first, it is dropped and logged. |
| NO PTT | The bound PTT device is not connected. |
| NO HOLD | The last press was too short to be a foot press (under 50 ms): a pulse-type device is suspected, so hold-to-talk is not trusted. |
| WAIT (recognising) | The transmission is closed and its recognition is not finished. |
| IDLE | None of the above: ready to transmit. |

**PILOT CUT** is a notice, not a TX state. It shows for 2 s (configurable) when a press interrupts the pilot (rule "interrupt", the default). TX itself shows TX at the same time.

Queue details (D-24): the *press* is queued, not speech. Nothing said while the pilot talks is transmitted or recognised; an early release drops the press and is logged. When TX opens, a side-tone click (default 20 ms, 1 kHz, -18 dBFS, `config/ui.json`) plays with the TX light. Pre-roll, minimum and maximum duration, clipped-start and key-to-speech all count from that moment. A queued press goes ahead of any further pilot reply.

`TransmissionController` implements all three rules (`TxConfig::pressDuringPilot`, names as in the scenario schema). Every blocked, queued, dropped or interrupting press produces an event for the log. The rule applies only while the pilot is speaking; during the reply delay a press always opens TX.

- The result line is replaced by the reason when a model has failed or a request was refused. Recording rows also show model and delay; a narrow row shortens the model name, never the delay.

- ATC examples: same S/D strip as replies (text field plus strip), without position, recording letter or recorder. Selecting one leaves the recorder empty with "ATC examples are not recorded". They generate the Vosk language-model corpus.
- "Say this" is the real reply template that uses the clip, filled with pool values, target in bold, numbers in spoken spelling ("zero niner"). If several templates use the clip, "Used in" lists them and steps through them.
- Status and SOP reference belong to the intent (D-25). Validated needs an SOP reference and can be set only by the instructor role; `validated_by` and `validated_at` are stored and shown beside the status. Editing a Validated intent returns it to Draft and clears both.
- Content is read from and written to `data/phraseology/`, the single source (D-45).
- Corpus caution: the current Vosk model has no word "niner" (02 §3.1), and Vosk ignores unknown words silently. The corpus generator must report words missing from the lexicon.
- S = STATIC: solid border, proportional font. D = DYNAMIC: dashed border, mono font, pool name; tap opens the pool in the row below. Readable without colour.
- Recording status on every chip is a letter as well as a dot: M missing (grey), R recorded (amber), A accepted (green). Position: INI / MED / FIN.
- Record toggles Start/Stop. Stop shows the waveform with the auto-trim region bright, removed silence dimmed, and draggable handles (48 px touch area).
- Keys: Space start/stop, Enter accept, R re-record, P play trimmed; Next/Previous missing. While a text field has focus these keys type text instead.
- The foot pedal may start/stop recording only while this screen is open and "Pedal" is on; it never opens a transmission here.
- The three panes do not reflow: the strip keeps two rows and scrolls, the pool row keeps one row and scrolls.

- Login (D-111): nobody is logged in at start. A trainee chooses an ID, without a PIN. The instructor enters the PIN; it is checked on a worker thread. After 5 wrong entries: "Wait 60 s". - Trainee record (D-112): ID code, optional name and rank, consent yes or no with the date of the answer. Only the instructor adds a record or changes consent (D-109). Records are not deleted. A speaker is the same record. Planned: 8 speakers, 4 dev and 4 test (D-42); the split belongs to session 93's manifest.
- A transmission is saved only if the switch is on and a trainee is logged in whose consent is yes. Otherwise it stays in memory. Line states: Saved on this machine only / Not saved: log in as a trainee / Not saved: no consent / Saving is off / Not saved: <reason>.
- The recording's JSON carries the ID only, never name or rank.
- Delete: instructor only, with confirmation. The line (time, role, recording, ID) is written to `deletions.log` first; if that fails nothing is deleted. The app never deletes the log.
- Low disk: a warning below `recordingsWarnFreeMb` (1000); saving stops below `recordingsMinFreeMb` (200, D-306). Export stays off (D-407).

## 6. QML structure

- `ui/theme/Theme.qml` (singleton: Dark, Night, High-contrast), `ui/components/`, `ui/screens/`, `ui/mock/`, `ui/fonts/`. C++ in `src/app/`.
- C++: `StatusController`, `RadioController`, `ExerciseController`, `LabController`, `TranscriptModel`, `StepModel`, `SessionModel`, `SettingsController`. QML is view only.
- Qt 6.2.4 limits: no `loadFromModule`, no `MultiEffect`; use `qt_add_qml_module` with a classic `engine.load()` URL; avoid any API newer than 6.2.
- Screens by `Loader`; only Active Communication stays resident during an exercise. `reuseItems: true`; transcript window capped at 200 entries, older paged from SQLite.
- No blur, shadows or Canvas. Waveform is a `QQuickPaintedItem`. Animations ≤ 150 ms, opacity/colour only; optional TX pulse.
- A mock backend (`--mock`) drives every screen with scripted events, used for Phase 1.

To be measured on the panel: frame time (`QSG_RENDER_TIMING=1`), UI process RSS, start-up time, for both resolutions if a 1080p display is ever used.
